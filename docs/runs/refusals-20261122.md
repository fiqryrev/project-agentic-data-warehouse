# Why the chat refused golden questions, and the fix (issue 34)

## Diagnosis

`uv run python -m llm.refusals` (reads only) rebuilt the 28 golden answers of the two provider
comparisons of M12 (`compare-20261122T0958`, `compare-20261122T1006`, every answer readable since
write mode dual) from the gateway's prompts: the agent's last model call holds the whole episode.

| Outcome | Ending | Answers | Used `retrieve` purpose sql |
| --- | --- | ---: | ---: |
| answered | | 15 | 15 |
| refused | tables_never_in_view | 5 | 0 |
| refused | tool_budget_spent | 5 | 0 |
| refused | other | 3 | 3 |

`tables_never_in_view`: every `run_sql` was refused with "Not in view: <table>. Retrieve it (its
exact name works) before using it." `tool_budget_spent`: the same, plus one query that ran,
until "No tool calls left". In all ten the agent only called `retrieve(purpose="information")`,
which lists tables briefly (the catalog view); Auto Ontology counts only a table shown in full
by the sql view as in view (`react/retrieve.py`, `seen_tables`). The agent then spent its 24 tool
calls on name variants of a table it had already found, and the chat answered "I couldn't write
a query".

The chat API had no way to drop the catalog view: the agent offers it unless the payload says
`calculation_only`, which only Auto Ontology's internal interactive flow sets.

## Fix

Overlay patch `0002-chat-api-calculation-only.patch` adds `calculation_only` to the chat API and
passes it to the agent; the golden runner and `make compare-providers` send it (the web UI does
not). No knob was changed.
